# 에이전트 7 — 토스증권 계좌 동기화 및 주문 실행

## 역할

`agent7_execution.py`의 동작을 설명하고 보존하는 작업 지침입니다. 에이전트 7은 에이전트 2가 만든 주문 계획을 모의 기록하거나, 명시적으로 허용된 경우 토스증권 Open API로 제출하며 계좌 현금·보유량을 동기화합니다.

## 입력과 결과

- 입력은 `OrderPlan`, 실행 모드, 실거래 최대 매수 한도와 토스증권 API 클라이언트입니다.
- 계좌 동기화는 매수 가능 USD, 환율, 대상 종목 보유 수량·평단을 조회해 상태와 동기화 결과를 반환합니다.
- 기본 실행 모드는 모의 실행입니다. 모의 실행에서는 실제 주문을 보내지 않고 주문별 모의 접수 결과를 기록합니다.
- 실거래에서는 LOC를 증권사 `LIMIT` 주문과 종가 유효기간(`CLS`)으로 변환하고, 일반 지정가는 `DAY`, 시장가 주문은 시장가 유형으로 전달합니다.
- `ExecutionResult`는 주문 접수·실패 건수와 상세 결과를 반환합니다. 접수 결과는 실제 체결 확정과 다릅니다.

## 지켜야 할 경계

- 실거래를 기본값이나 묵시적 동작으로 만들지 않습니다. 인증 정보가 없으면 실거래 실행을 허용하지 않습니다.
- 실거래 전 양수 매수 한도, 주문 가격·수량 유효성, 기존 미체결 주문, 당일 이미 체결된 매수, 실제 USD 매수 가능 금액, 매도 가능 보유 수량과 날짜별 중복 실행 잠금을 확인합니다.
- 사전 검증이나 계좌·주문 내역 조회가 실패하면 주문을 보내지 않습니다. 성공한 것처럼 보이는 기본값이나 오래된 값을 사용하지 않습니다.
- 주문은 순차 제출되며 일부 접수 후 실패하면 전체를 자동 취소할 수 없습니다. 실패 이후 재실행 전에 실제 주문 내역을 확인하도록 명확히 알립니다.
- 비밀 키, 토큰, 계좌 인증 정보를 로그·보고서·오류 메시지에 노출하지 않습니다.
- 전략 주문을 임의로 재계산하거나 바꾸지 않습니다. LOC 등의 증권사 변환이 전략 규칙과 일치하는지 확인하고, 전략 규칙 자체 변경은 [공통 지침](./AGENTS.md)을 따릅니다.

## 수정 시 확인

- 모의 실행과 실거래의 격리를 테스트합니다. 모의 실행에서 외부 주문 API를 호출하지 않는지 확인합니다.
- 각 사전 검증 실패가 주문 제출 전에 멈추는지, 주문 접수 결과와 체결 정산이 구분되는지 테스트합니다.
- 부분 제출 후 오류, 중복 실행 잠금, 실제 계좌 보유량·매수 가능 현금과 주문 계획의 경계를 확인합니다.
