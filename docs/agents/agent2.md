# 에이전트 2 — 무한매수 전략 및 백테스트

## 역할

`agent2_strategy.py`의 동작을 설명하고 보존하는 작업 지침입니다. 에이전트 2는 입력된 전략 상태와 완료된 기준 종가를 바탕으로 일일 주문 계획을 계산하고, 확인된 체결을 전략 상태에 반영하며, 과거 가격 자료로 전략을 시뮬레이션합니다.

## 입력과 결과

- `StrategyState`에는 종목, 회차, 분할 수, 목표 수익률, T값, 평단, 보유량, 잔여 현금, 모드가 들어갑니다.
- 주문 생성에는 기준 종가, 선택적인 최근 5거래일 종가, 기준일을 사용합니다.
- `OrderPlan`에는 1회 매수금, 별%, 별지점, 목표 매도가와 매수·매도 주문 목록이 담깁니다.
- 체결 반영에는 실제 체결 가격·수량·주문 태그를 사용해 보유량, 평단, 현금, T값, 실현손익, 회차 상태를 갱신합니다.
- 백테스터는 OHLC 가격 자료를 일자별로 진행하며 완료 회차, 평가 자산, 수익률, 최대 낙폭 등을 반환합니다.

## 지켜야 할 경계

- 이 파일은 주문 계산의 핵심입니다. 공식 규칙 참고 페이지와 저장소의 [공통 전략 규칙 지침](./AGENTS.md)을 먼저 확인하지 않고 매매 규칙을 바꾸지 않습니다.
- 현재 코드의 계산식이나 기존 테스트를 공식 규칙의 근거로 간주하지 않습니다. 참고 자료에서 규칙을 확인하고 기대값을 별도로 계산해 검증합니다.
- 주문 가격·수량, 반올림/버림, 매수·매도 조건, 체결 시 T값, 회차 종료, 소진 및 리버스 모드의 동작을 서로 일관되게 유지합니다.
- 에이전트 2는 주문 계획만 만듭니다. 실제 계좌 상태 확인과 주문 제출은 에이전트 7의 책임입니다.
- 백테스트 결과는 시뮬레이션입니다. 실제 체결, 거래 비용, 시장 충격 또는 수익을 보장하는 결과로 표현하지 않습니다.
- 시세 자료가 없거나 올바르지 않은 경우 임의의 가격을 사용하지 않습니다. 거래 실행 흐름에서 기준 가격을 누락·대체하는 동작을 추가하지 않습니다.

## 수정 시 확인

- 영향을 받는 규칙을 공식 참고 페이지와 대조하고 모호하거나 다른 내용은 임의 해석하지 않습니다.
- 독립 산출한 기대값으로 전반전·후반전·주문 경계·부분 체결·동일일 매수/매도·회차 종료·리버스 모드 테스트를 추가하거나 갱신합니다.
- 주문 계획뿐 아니라 체결 정산과 에이전트 7의 증권사 주문 변환까지 검증합니다.
- 전략 규칙 관련 검증 절차와 출처는 저장소의 [공통 지침](./AGENTS.md)을 따릅니다.
## 회차 손익 재투자

### 새 회차 시작자산 질문

2회차부터 보유량과 T값이 모두 0인 새 회차에서는 주문표 생성 전에 설정된 텔레그램 채팅으로 시작자산을 한 번 질문합니다. 질문 메시지에 답장으로 달러 금액(예: `30000`, `30,000.00`)을 입력하면 해당 금액을 적용합니다. 기존 회차 진행 중에는 질문하지 않습니다.

기본 대기 시간은 300초이며 `.env`의 `CYCLE_CAPITAL_WAIT_SECONDS`로 0~3600초 범위에서 변경할 수 있습니다. 응답이 없거나 통신이 실패하면 자동 계산한 시작자산을 유지합니다. 텔레그램 미설정 시 대기 없이 진행합니다. 기한이 지난 답장이나 다른 메시지에 대한 답장은 반영하지 않습니다. 입력은 0 초과, 계좌 가용 현금 이하, 소수 둘째 자리까지 허용합니다.

질문·응답 상태는 `data/cycle_capital_requests.json`에 저장하여 같은 회차에 다시 질문하지 않습니다. 재시작 시 확정한 선택을 복원합니다. 선택 금액보다 남는 현금은 `excluded_cash`로 일지에 저장하여 이후 증권사 잔고 동기화에서도 투자금으로 다시 편입하지 않습니다. 답변 대기는 새 회차 주문표 생성과 주문 제출 전에 수행합니다.

텔레그램 답장은 [공식 Bot API](https://core.telegram.org/bots/api#getupdates)의 `getUpdates`로 조회합니다. 같은 봇의 별도 업데이트 수신기나 webhook이 있으면 충돌할 수 있으며, 이때는 자동 계산 금액으로 진행합니다.

질문·대기 절차는 사용자가 요청한 운영 절차입니다. 참고 페이지의 회차 시작 시 원금을 선택하는 설명과 대조했으며 미해결 규칙 충돌은 없습니다. 모의 응답 테스트와 별도 임시 상태를 이용한 실제 텔레그램 답장 수신 테스트를 통과했습니다. 실주문과 실제 장부는 변경하지 않았습니다.

전량 매도로 회차가 끝나면 매도 대금까지 반영한 전략 장부의 남은 현금을 다음 회차 시작 원금(`initial_budget`)으로 사용합니다. 수익과 손실 모두 반영하며, 이미 현금에 들어 있는 실현 손익을 다시 더하지 않습니다. 쿼터매도만으로는 회차 시작 원금을 바꾸지 않습니다.

일지에 회차 시작 원금을 저장하여 다음 실행에서도 복원합니다. 이 필드가 없는 기존 일지는 설정 원금으로 복원합니다. 설정 파일의 최초 투자금은 변경하지 않습니다. 계산은 기존 체결 가격·수량 기준이며 수수료·세금은 별도 차감하지 않습니다.
